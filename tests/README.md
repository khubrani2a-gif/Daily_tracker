# اختبارات مفكرتي اليومية · Tests

اختبارات آلية بواجهة Playwright (Chromium بلا واجهة) تُحمّل `index.html` فعليًا في المتصفّح
وتتحقّق من السلوك عبر `localStorage`/DOM وخطّافات مزامنة داخلية للقراءة فقط.

## التشغيل

```bash
# يتطلّب Playwright + Chromium. حدّد المسار إن لم تكن الحزمة مثبّتة عالميًا:
export PW_PATH=/path/to/node_modules/playwright     # اختياري
node tests/sync-contract.test.js          # عقد المزامنة (بنود المراجعة الحاجزة)
node tests/coordinator-containment.test.js # المنسّق العام + عزل الأعطال + تزامن عبر الأجهزة
node tests/fixed-expenses.test.js          # الالتزامات الثابتة + توفيق المثيلات عند التحميل
node tests/expenses-travel.test.js         # مصاريف السفر + التقارير + عدم تجاوز أفقي
node tests/startup-hardening.test.js       # إقلاع سليم رغم بيانات مصاريف مشوّهة
```

كل ملف يطبع `RESULT: N passed, M failed` وينهي برمز خروج غير صفري عند أي فشل
أو أي خطأ JS في الصفحة.

## ماذا يغطّي `sync-contract.test.js`

يغطّي بنود المراجعة الحاجزة لإصلاح v99:

1. **عقد Expenses كبقيّة الأقسام** — قراءة «الخادم أولًا ثم الكاش صراحةً»؛ عدم تخطّي الكاش
   لمجرّد انقطاع الاتصال؛ `expPushRemote` يُعيد وعدًا بنتيجة `{ok}`؛ انتظار كتابة المصالحة؛
   عدم الدفع بعد رجوعٍ للكاش؛ حالة مُهيكلة (success/cacheFallback/failed)؛ وعدم تحديث
   «وقت آخر مزامنة خادم» بعد قراءة كاش.
2. **أقفال in-flight حقيقية لكل قسم** — تشغيلان متزامنان لقسمٍ واحد ⇒ الثاني `throttled`.
3. **حراسة الجيل (`_syncRunGen`)** — التشغيل الأقدم ليس هو الأحدث، فلا يحدّث الحالة المرئية.
4. **رؤية فشل كتابة المصالحة** — فشل الكتابة يظهر `failed` ولا يُبلَّغ نجاحًا.

## حدود صادقة (Honest limitations)

- هذه **ليست** محاكاة Firestore حقيقية ولا ثلاثة عملاء فيزيائيين. تستخدم بديلًا
  في‑الذاكرة أمينًا لواجهة compat يميّز `{source:"server"}` عن `{source:"cache"}`،
  ويحقن أعطال الخادم/الكتابة والتأخير وعدّاد الكتابات. التقارب «عبر الأجهزة» مُحاكى
  عند حدّ الواجهة (نفس متجر الذاكرة بين سياقات المتصفّح)، لا عبر الشبكة.
- التحقّق النهائي على أجهزة حقيقية (استئناف التطبيق بعد نوم الخلفية، كاش IndexedDB فعلي)
  يبقى خطوة يدوية خارج نطاق هذه المجموعة.
