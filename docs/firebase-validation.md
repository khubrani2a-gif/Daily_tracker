# حماية Firebase والتحقق من المزامنة

## ما تم تنفيذه

- ملف `firestore.rules` يسمح للمستخدم المسجّل بقراءة وكتابة مستنداته فقط في `days` و`meta` و`hifzSegments` و`readingItems` و`readingSessions`. لا يمنح إذنًا تلقائيًا للمجموعات الفرعية أو المسارات الجديدة.
- اختبار قواعد كل مجموعة: القراءة والاستعلام والكتابة والحذف لصاحب الحساب، ورفض الوصول لحساب آخر أو زائر غير مسجّل.
- اختبار التطبيق في جلستي Chromium مستقلتين مع نسخة Firebase SDK نفسها المستخدمة في الموقع (10.14.1) وخادم Firestore Emulator الفعلي: تعديل دون اتصال، تعديل آخر على الجهاز المقابل، ثم عودة الاتصال ودمج التغييرين.
- إصلاح التنبيهات المحلية: تسجيل نجاح التذكير بعد قبول عرضه فقط؛ الفشل يسمح بإعادة المحاولة، مع منع المحاولات المتزامنة داخل الصفحة.

## إعادة الاختبارات

يلزم Node.js 24 وJava 21 وChromium:

```sh
npm ci
npx playwright install chromium
npm test
npm run test:firebase
```

اختبارات Firebase تستخدم مشروعًا وهميًا ثابتًا `demo-daily-tracker` ومحاكيًا محليًا على `127.0.0.1:8080`. لا تستعمل حسابات المستخدمين أو قاعدة الإنتاج. هوية الاختبار مُحاكاة، بينما Firebase SDK ونقل البيانات ومحرك قواعد Firestore حقيقية. اختبارات GitHub تشغّل المجموعتين قبل نشر الموقع.

## نشر قواعد الإنتاج

المشروع الحالي: `daily-tracker-85609`.

بعد تسجيل الدخول الآمن من بيئة لها صلاحية نشر قواعد المشروع:

```sh
npx firebase login
npx firebase deploy --only firestore:rules --project daily-tracker-85609
```

التحقق والنشر منفصلان: نشر GitHub Pages لا ينشر هذه القواعد. يجب مراجعة القواعد المنشورة حاليًا ومقارنة أي مجموعات يستخدمها عميل آخر قبل استبدالها. لا تضع مفاتيح حساب الخدمة أو رموز الدخول في المستودع أو المحادثة.

## ما لم يُتحقق منه أو يُفعّل

- لم تتوفر صلاحية إدارة Firebase في بيئة التنفيذ؛ `firebase projects:list` أعاد `Failed to authenticate`. لذلك لم تُقرأ أو تُغيّر قواعد الإنتاج، ولا ندّعي أن القواعد المختبرة هي القواعد المنشورة.
- التنبيهات عند إغلاق التطبيق لم تُفعّل. تحتاج Firebase Cloud Messaging، تسجيل اشتراك الجهاز، معالج رسائل في service worker، وخادم جدولة موثوقًا يراعي المنطقة الزمنية وإلغاء التنبيه عند إكمال المهمة أو تسجيل الخروج. لا يكفي مؤقّت داخل الصفحة أو service worker. يجب التحقق من إعدادات المشروع وخطة الفوترة قبل اختيار ونشر الخادم؛ Cloud Functions المجدولة تتطلب إعداد فوترة.
- الاختبارات أعلاه ليست اختبارًا على هاتف المستخدم أو جهازه الثاني، ولا تختبر Google OAuth أو إعدادات المتصفح الفعلية في الإنتاج. يظل اختبار الأجهزة الفعلية مطلوبًا للتأكد من هذه الجوانب.
